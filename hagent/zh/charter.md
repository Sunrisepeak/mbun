# hagent 宪法(charter)

[English](../charter.md) · 以英文本 [`../charter.md`](../charter.md) 为准。

构建者与 agent 在本仓协作的宪法。刻意保持简短。本宪法与其它文档冲突时,以本宪法为准。

(「构建者」= 负责创作与判断的人——见 §2。)

## 1. 角色

| 角色 | 拥有 | 不得 |
| --- | --- | --- |
| **构建者** | 架构、决策、品位、规范;读懂并 review 以自己名义合入的内容(§3)。 | —— |
| **维护者** | 受保护面(§5);授予写权限(§4)。是拥有治理权的构建者。 | —— |
| **agent 贡献者** | 实现、测试、changelog、开 PR —— 以构建者的身份提交(§3)。 | 自 merge 受保护面(§5);自授写权限。 |
| **agent 审查者** | 审查/批准常规 PR;绿且非受保护面时 merge。 | 无维护者参与就批准受保护面的改动。 |

## 2. 分工:执行 vs 创作

按**性质**分工,而非数量。

- **agent 执行**:实现、测试、PR 审查、常规改动的 merge。
- **构建者创作与判断**:架构、决策、品位、规范,以及少数特殊的细节设计/优化。构建者是
  参与构建与创作的人,而非单纯守门。
- agent 承担 90%+ 吞吐是执行占绝大部分体量的**结果**,不是治理规则本身。

## 3. 归属:每个操作都归属到构建者

即使工作由 agent 完成:

- **主作者与主签名是构建者**(commit `Author` = 构建者的邮箱;`Signed-off-by:` =
  构建者)。
- **agent 是 co-author**,用 `Co-authored-by:` 行记录其模型(各工具的具体写法见
  [contributing.md](contributing.md#commit-规范))。
- 既然贡献归属到构建者,构建者就**必须读懂**自己提交的 diff——这是默认要求,而非特例。

具体 commit 格式见 [contributing.md](contributing.md#commit-规范)。这样既保留单一、
归属构建者的问责链,又让 agent 贡献可度量。

## 4. 权限层级

信任是一条阶梯;agent 以同一规则获得相同层级。committer 以上的层级仍在完善。

| 角色 | 授予 | 如何获得 |
| --- | --- | --- |
| **Triager 分诊** | 分诊:打标签、确认/复现 issue、验证 issue 与 PR、请求修改,并在 PR 上跑 CI。 | **自助**:**≥ 3 个已合入 PR**(含 agent)。 |
| **Committer 提交者** | 写权限(push / merge)。 | 相关模块背景**且**有重要贡献;**须维护者批准**。 |
| **模块维护者** | 某模块的审查与决策权。 | —— |
| **项目维护者** | 总体治理与受保护面(§5)。 | —— |

这是完整身份与权限模型(路线图模块 ⑤)的精简先行版。

## 5. 受保护面(须维护者签字)

改动以下任一 = **宪法级**变更:agent **不得**自 merge,须维护者签字——且**双向**
(agent 提出则维护者批准;构建者提出的改动同样要留痕并被审查)。

- `hagent/**` —— 本系统自身
- `.agents/skills/**` —— agent 操作规程(SOP)
- `CONTRIBUTING.md` / `AGENTS.md` / `CLAUDE.md` / `GOVERNANCE.md` —— 根指针
- `.github/workflows/**` —— CI
- `CODEOWNERS`(未来)与 `LICENSE`

> 本宪法声明该清单;其**强制**(CODEOWNERS、分支保护)属路线图模块 ③。

## 6. 贡献生命周期

```
认领 ──▶ 建分支 ──▶ TDD(red→green) ──▶ 收集证据 ──▶ 开 PR(模板)
                                                          │
                                                          ▼
                                  agent 审查 ──▶ 闸门(证据 / 风格 / 回归)
                                                          │
                        ┌─────────────────────────────────┴──────────────────┐
                        ▼                                                      ▼
                 非受保护面 且 绿                                   受保护面 或 高风险
                        │                                                      │
                        ▼                                                      ▼
                 agent 可自 merge                                   须维护者签字
                        │                                                      │
                        └────────────────────────────┬──────────────────────────┘
                                                      ▼
                            merge ──▶ 记入 changelog.md + 署名 trailer
```

## 7. 验收底线

引 mbun 的 [`tdd-workflow`](../../.agents/skills/tdd-workflow/SKILL.md):

- `compat/` 下上游语料是**只读输入** —— 可做移植性适配,但不得弱化断言语义。
- **无证据不得声称完成** —— 套件 before→after 计数 + 复现命令(见
  [contributing.md](contributing.md#证据))。
- 可能 spawn/hang 的测试只经沙箱运行(`tools/integration/safe-test.sh` /
  `bounded_run.py`)。
